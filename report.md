# Отчёт по анализу аномалий в журнале заявок на закупку

## 1. Инструменты и воспроизводимые шаги анализа

Анализ проведён на языке Python 3 с использованием **только стандартной библиотеки** (`csv`, `datetime`, `collections`). Внешние зависимости (`pandas`, `numpy` и т.п.) не использовались, что делает запуск возможным на любой машине с установленным Python.

Воспроизводимые шаги:
1. Чтение `students.csv` через `csv.DictReader` с кодировкой `utf-8-sig`.
2. Парсинг поля `Timestamp` в объект `datetime` (с отбрасыванием часового пояса для упрощения арифметики — все события в одном часовом поясе UTC+03:00).
3. Группировка событий по `ProcessInstanceId` в словарь `defaultdict(list)`, сортировка внутри каждой группы по `EventIndex`.
4. Для каждого процесса последовательно проверяются три критерия аномальности (см. раздел 3).
5. Результаты записываются в `anomalies.csv` через `csv.DictWriter` с кодировкой `utf-8-sig`.

Код анализа (`analysis_simple.py`) прилагается и запускается командой `python analysis_simple.py` без предварительной установки каких-либо пакетов.

## 2. Обычное поведение и обоснование

На основе анализа 1000+ процессов выявлен типичный успешный маршрут:
- `Регистрация заявки` (system) → `Проверка заявки` (specialist) → `Согласование руководителем` (manager) → `Согласование бюджета` (finance) → [`Проверка договора` (legal), если RequestType=contract] → `Исполнение заявки` (procurement) → `Завершение` (fulfilled).
- При возврате (`return`) маршрут проходит через `Доработка заявки` (requester) и возвращается на `Проверку заявки`.
- Ожидаемая календарная длительность этапов согласования — от 15 минут до нескольких дней, что связано с рабочим календарём (Пн–Пт, 09:00–18:00) и временем ожидания в очереди.

## 3. Критерии поиска аномалий

Были выбраны строгие критерии, отличающие нарушение процесса от допустимой вариативности:

1. **Нарушение разделения ролей (SoD)**: наличие события `task_completed` на этапе `Согласование руководителем`, где `Role` = `requester`. Заявитель не должен иметь прав на одобрение собственной заявки.

2. **Признаки автоматизированного согласования (бот)**: календарная длительность этапа (`task_completed` − `task_created`) составляет **менее 1 минуты** для этапа `Согласование руководителем`. Это физически исключает ручное ознакомление с документом и указывает на скриптовый авто-аппрув.

3. **Пропуск обязательного этапа**: процесс достиг статуса `process_completed` с результатом `fulfilled`, но в его журнале отсутствует событие `task_completed` для одного из обязательных этапов — в частности, `Согласование руководителем`. Это означает, что заявка прошла по маршруту `Проверка → Бюджет → Исполнение`, минуя руководителя, что является грубым нарушением бизнес-процесса.

*Примечание*: Этап `Внеплановая проверка` не считался аномалией, так как в условии прямо указано, что её оправданность нельзя установить только по редкости.

## 4. Полученные результаты

Всего выявлено **32 записи об аномалиях** в 32 уникальных процессах:
- **8 процессов** с нарушением разделения ролей (заявитель сам согласовал заявку).
- **8 процессов** с признаками бот-активности (сверхбыстрое согласование, 0.1–0.3 минуты на этап).
- **16 процессов** с пропуском обязательного этапа `Согласование руководителем` при успешном завершении заявки (статус `fulfilled`). Маршрут в этих случаях прошел напрямую от `Проверки заявки` к `Согласованию бюджета`, что является грубым нарушением бизнес-процесса.

*Показательный пример*: в процессе `10daf811-5f75-5dbf-a76c-b4f818fc2e2d` маршрут прошел напрямую `Проверка заявки (accept) → Согласование бюджета (accept) → Исполнение заявки (accept) → Завершение (fulfilled)`, полностью минуя этап руководителя.

## 5. Ложные срабатывания, ограничения и случаи для ручной проверки

- **Ограничение по времени**: анализ использует календарную длительность. Теоретически сверхбыстрое согласование возможно из-за сбоя таймстемпов, но массовый характер (8 процессов) это исключает.
- **Незавершённые процессы**: открытые заявки на дату среза (01.07.2026) не считались аномалией, если их текущий этап не нарушал критерии.
- **Ручная проверка**: процессы с пропуском этапа требуют аудита настроек маршрутизации в системе, так как это системная ошибка, позволившая заявке пройти без виза руководителя.
- **Внеплановая проверка**: 8 процессов с этим этапом намеренно не включены в аномалии, так как их оправданность требует бизнес-обоснования, а не только статистической редкости.

## 6. Использование AI

Для первичного исследования структуры данных, доработки скриптов агрегации на Python и формулирования гипотез использовалась языковая модель (Qwen). Все выявленные аномалии были перепроверены путём прямого просмотра сырых строк журнала (`students.csv`) для соответствующих `ProcessInstanceId`, чтобы исключить галлюцинации модели и подтвердить факты (роль, длительность, порядок событий).
